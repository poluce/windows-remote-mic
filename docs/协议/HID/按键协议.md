# HID 按键协议（RC003）

> 状态：真机验证（2026-09-01）
> 关联：`docs/协议/ATVV/协议.md`、`AGENTS.md` 3.5 节

## 普通按键走 HID

遥控器按键通过蓝牙 HID 键盘报告上报，usage page = `0x07`（Keyboard）。
真实报告路径：**GATT 通知 → 8 字节队列项 → HOGP 驱动转发 → 内核 HID 驱动**。

## Windows Raw Input 缺口

- 返回 `0xF1`、TV `0x35`、音量 `0x80/0x81` 在 Windows Raw Input 下缺失（实测）
- 原因：这四个键属于「应用命令类按键」，被 HOGP 层从键盘输入通道分流，Raw Input 和 WH_KEYBOARD_LL 钩子都看不到
- 系统仍认识并原生处理它们（返回 → 浏览器后退、TV → 启动媒体选择、音量 → 系统音量变化，走 WM_APPCOMMAND 应用命令通道）
- 解决方案：Frida 旁路（WUDFHost HID-over-GATT 驱动层），四个键都能捕获到

## 拦截（吃掉）模式

- 默认开启，连接页「拦截 HID 按键信号」开关可切换，热更新无需重新注入
- 拦截点：HOGP 驱动 `0x20080` 的 memcpy 转发点（8 字节队列项 → WDF 请求缓冲区）
- 探针先把清零前的原始报告转成 9 字节 IOCTL 格式（`01 00 00` + 3 个 usage）上报应用，再把源缓冲区清零——系统 HOGP 层看不到任何遥控器按键，只由本应用注入映射动作
- 音频流（ATVV Audio 特征）不经过该拦截点，完全不受影响

## 按键行为约定

- 触发类型：单击 / 双击 / 长按（12 个普通键）；**按下 / 松开（仅麦克风，PTT）**
- 长按只触发一次，无按住连发
- 长按阈值默认 550ms、双击窗口默认 300ms，映射页可设置（`config.json` 的 `long_press_ms` / `double_click_ms`），保存后热更新
- 麦克风 Press/Release 是**长按门控**：按住达到长按阈值才发 Press，长按结束（松开）才发 Release；快速点按不产生事件
- 麦克风默认映射：Press → Voice（Win+H）、Release → Voice（Win+H）；可在映射页改成任意动作（如第三方语音助手）
