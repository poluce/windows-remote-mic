## 3. 按键信号编码

### 3.1 物理按键、HID Usage、Windows VK

RC003 的按键使用 **HID 键盘页（Usage Page `0x07`）**。

| 物理按键 | HID Usage | Windows VK |
| --- | --- | --- |
| 麦克风/语音 | `0x3E` | `116` (F5) |
| 返回 | `0xF1` | `166` |
| 确定 | `0x28` | `13` (Enter) |
| TV | `0x35` | `180` |
| 主页 | `0x4A` | `36` (VK_HOME) |
| 右 | `0x4F` | `39` |
| 左 | `0x50` | `37` |
| 下 | `0x51` | `40` |
| 上 | `0x52` | `38` |
| 菜单 | `0x65` | `93` |
| 电源 | `0x66` | `255` |
| 音量 + | `0x80` | `175` |
| 音量 − | `0x81` | `174` |

> 备注：`0xF1` 位于 HID 键盘页厂商保留区（0xE8–0xFF）；`0x35` 对应 Consumer/媒体选择类功能；`0x4A` 在 Windows 上映射为 VK_HOME(36)。消费类 Usage Page（`0x0C`）也存在返回/主页/音量/菜单等编码，Windows 可能走 `WM_APPCOMMAND`。

### 3.2 Windows 通路差异（真机结论）

> 指 Windows 下哪些 API/通道能收到该遥控器的按键。HOGP = HID over GATT（蓝牙 HID 通道）。

| 按键 | Raw Input | 低级键盘钩子（WH_KEYBOARD_LL） | HOGP 驱动层捕获 |
| --- | --- | --- | --- |
| 上/下/左/右/确定/主页/菜单/电源 | ✅ | ✅ | ✅ |
| 返回 `0xF1`、音量 `0x80/0x81`、TV `0x35` | ❌ 系统过滤 | ❌ | ✅ 需在 HOGP 驱动层捕获 |
| 麦克风 `0x3E` | ✅（部分条件下） | — | ✅ |

## 4. 协议：ATVV（Android TV Voice over BLE）

### 4.1 GATT 服务与特征

| 名称 | UUID | 方向 | 用途 |
| --- | --- | --- | --- |
| ATVV Service | `AB5E0001-5A21-4F05-BC7D-AF01F617B664` | — | 语音服务 |
| TX | `AB5E0002-...` | Host → Remote | 主机命令（写） |
| Audio (RX) | `AB5E0003-...` | Remote → Host | 音频通知 |
| Control (CTL) | `AB5E0004-...` | Remote → Host | 控制通知 |

> 常见社区也写作 `ab5e0002/0003/0004`（同属上述 UUID）。

### 4.2 命令 / 事件 opcode

**Host → Device（TX）：**

| 命令 | 载荷 | 说明 |
| --- | --- | --- |
| GET_CAPABILITIES_V10 | `0A 01 00 00 03 03` | 能力查询 |
| MIC_OPEN | `0C ...` | 打开麦克风；不同设备载荷长度不同（见 4.7 坑） |
| MIC_CLOSE | `0D ...` | 关闭麦克风；载荷会影响是否真正停止（见 4.7 坑） |
| MIC_EXTEND | 社区 v1.0+ 用于长语音续期 | 部分设备用于 keepalive，静默续期 |

**Device → Host（Control 通知，首字节 opcode）：**

| 事件 | opcode | 说明 |
| --- | --- | --- |
| AUDIO_STOP | `0x00` | 语音流结束 |
| AUDIO_START | `0x04` | 语音流开始 |
| MIC_BUTTON | `0x08` | 麦克风键按下事件（RC003 未观察到经此通道发送） |
| AUDIO_SYNC | `0x0A` | 解码器同步（部分设备） |
| CAPS | `0x0B` | 能力协商响应 |
| MIC_OPEN_ERROR | `0x0C` | MIC_OPEN 失败（某些设备） |

> 社区也把 0x08 称为 START_SEARCH，把 0x0B 称为 GET_CAPS_RESP / CAPS_RESP，含义相同。

### 4.3 RC003 观察到的会话流程

```
连接 → 启用 Audio/Control 通知 → 发送 GET_CAPABILITIES_V10
按下麦克风键：
  CTL  ← AUDIO_START
  Audio ← 120 字节 IMA ADPCM 帧（持续）
松开麦克风键：
  CTL  ← AUDIO_STOP
  HID 0x3E release（同时）
```

### 4.4 音频格式

| 项 | RC003 | 其他 ATVV 设备（对照） |
| --- | --- | --- |
| 编码 | IMA/DVI ADPCM 4-bit | 同 |
| 采样率 | **16 kHz** | 部分设备为 8 kHz；Chromecast remote 为 16 kHz |
| 每字节采样 | 2 | 2 |
| 高/低 nibble | **高 nibble 优先** | 同 |
| 默认帧长 | **120 字节** | G20S 134B；Chromecast 160B |
| 帧带 header？ | RC003 裸 120B 连续流 | G20S 134B 带 6B header；Chromecast 160B 无 header 连续流 |

**RC003 相关音频帧格式：**

| 帧格式 | 采样率 | 说明 |
| --- | --- | --- |
| 120B 裸 ADPCM | 16kHz | RC003 常见格式 |
| 126B 带同步头 | 16kHz | 有社区实现对 RC003 兼容；含同步/AUDIO_SYNC 相关头 |
| 134B（6B header + 128B ADPCM） | 8kHz | 其它 ATVV 设备（G20S） |
| 160B 无 header 连续流 | 16kHz | 其它 ATVV 设备（Chromecast Remote） |

> ATVV 在不同设备上存在“带 DVI header 的 134B 帧”（G20S）与“裸连续 160B 帧”（Chromecast）等变体。RC003 常见为 **120B 裸帧、16kHz**。

### 4.5 语音键与固件差异

- RC003 语音键会同时产生 ATVV 语音事件和 HID 键。
- 多数固件中 HID 键编码为 `0x3E`（键盘 F5）。
- 有实现观察到 RC003-MS 固件为 KEY_F5；另有环境观察到 KEY_F9。

### 4.6 协议版本与长语音 keepalive

ATVV 存在 v0.4 与 v1.0 差异，可从 `CAPS_RESP` 自动识别：

| 版本 | 长语音 keepalive | 行为 |
| --- | --- | --- |
| v1.0+ | `MIC_EXTEND` | 静默续期，无响应/不中断 |
| v0.4 | `MIC_OPEN`（回退） | 设备回 `AUDIO_START` 并重置序列计数，但音频不中断 |

- 硬件有“Audio Transfer Timeout”（常见 15–60s），长时间语音必须周期性 keepalive，否则遥控器会停止推流。

### 4.7 RC003 注意事项

1. ✅ **RC003 语音走 GATT（ATVV），不走 HID 内嵌 ADPCM**。旧 VoHoGP（ADPCM 嵌入 HID report）不适用于 RC003。
2. ⚠️ **空闲广播/连接行为（社区经验）**：ATVV 遥控器空闲时可能不持续广播，扫描方式可能连不上；更可靠的是对已配对设备直接连接。此点仍需在 RC003 上系统验证。

## 5. 尚未验证 / 待探索事项

- ❓ **MIC_OPEN / MIC_CLOSE 在 RC003 上的真实时序与载荷**：RC003 目前观察到自动 AudioStarted/Stopped，是否必须/何时需要主动发送尚未完全验证。
- ❓ **RC003 是否有 126B 带同步头帧固件**：有社区实现支持，但 RC003 上未确认。
- ❓ **RC003 语音键是否会出现 F9 固件**：已知多数为 F5（`0x3E`），F9 仅在其它环境出现。
- ❓ **ATVV 长语音 keepalive（MIC_EXTEND）**：RC003 长按超过硬件超时后的行为未验证。
- ❓ **主页/菜单键真机单测**：已能收到，但仍待系统化补测。
- ❓ **RC003 是否原生支持双击语义**：固件/协议是否区分快速两次短按，尚未验证。
- ❓ **不同 RC003 固件/批次的行为差异**：按键、音频帧、语音键 code 可能随固件变化。
