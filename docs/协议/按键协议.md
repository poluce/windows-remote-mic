# HID 按键协议（RC003）

> 对象：RC003 / 小米蓝牙语音遥控器 2 Pro 的按键编码与 HID 通路。
> 可信度：✅ 实证 / ⚠️ 社区/推断 / ❓ 未验证。

---

## 1. 按键通道

RC003 的按键通过蓝牙 HID 键盘报告上报，usage page = `0x07`（Keyboard）。

语音流不经过 HID，走 ATVV（见 `ATVV-协议.md`）。

---

## 2. 按键 Usage 表

| 物理按键 | HID Usage | Windows VK | 备注 |
| --- | --- | --- | --- |
| 麦克风/语音 | `0x3E` | `116` (F5) | 同时产生 ATVV 语音事件与 HID 键 |
| 返回 | `0xF1` | `166` | 厂商自定义（0xE8–0xFF 保留区） |
| 确定 | `0x28` | `13` (Enter) | |
| TV | `0x35` | `180` | |
| 主页 | `0x4A` | `36` (VK_HOME) | Windows 映射为 VK_HOME，不是 VK_BROWSER_HOME |
| 右 | `0x4F` | `39` | |
| 左 | `0x50` | `37` | |
| 下 | `0x51` | `40` | |
| 上 | `0x52` | `38` | |
| 菜单 | `0x65` | `93` | |
| 电源 | `0x66` | `255` | |
| 音量 + | `0x80` | `175` | |
| 音量 − | `0x81` | `174` | |

> 消费类 Usage Page（`0x0C`）也存在返回/主页/音量/菜单等编码，Windows 可能走 `WM_APPCOMMAND`。

---

## 3. Windows 通路差异

| 按键 | Raw Input | WH_KEYBOARD_LL | HOGP 驱动层 |
| --- | --- | --- | --- |
| 上/下/左/右/确定/主页/菜单/电源 | ✅ | ✅ | ✅ |
| 返回 `0xF1`、音量 `0x80/0x81`、TV `0x35` | ❌ | ❌ | ✅ |
| 麦克风 `0x3E` | 部分条件下 | — | ✅ |

- 返回/音量/TV 在 Windows 上被 HOGP 层从键盘输入通道分流，Raw Input 和低级键盘钩子收不到。
- 系统仍会原生处理这些键（返回 → 浏览器后退、TV → 媒体选择、音量 → 系统音量，走 WM_APPCOMMAND）。
- 若要在应用层捕获这些键，需要在 HOGP 驱动层拦截。

---

## 4. 语音键固件差异

- RC003 语音键多数固件编码为 `0x3E`（键盘 F5）。
- 有实现观察到 RC003-MS 固件为 KEY_F5；另有环境观察到 KEY_F9。
- RC003 的 ATVV Control 通道未观察到 `MIC_BUTTON (0x08)` 事件，语音键的按下/松开主要体现在 HID 键与 ATVV 音频流状态上。
