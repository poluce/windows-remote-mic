Remote Mic · Design Spec

全应用视觉统一 + 现代化 + 轻毛玻璃（设计稿 v1）

目标：一套统一的色调与控件语言，现代但不炫技；毛玻璃只用在「浮在内容之上」的界面层， 内容是清晰的磨砂纸而不是一片糊。布局沿用现有信息结构，不做功能改版。

状态：已全部实现并通过真机验证（2026-10-24）

01设计原则

五条规则决定后面所有取舍；冲突时按编号靠前的优先。

1

一个强调色

全应用只保留一种钢蓝（#2B6FC0）。其它颜色只表达语义，不再用颜色区分「页面」。

2

玻璃只给浮层

侧栏、对话框、下拉、快捷菜单用真模糊；内容卡片用半透明磨砂，避免几十层滤镜。

3

冷灰四级文字

灰阶统一到冷灰（slate），与图标、快捷菜单已有色系一致；文字只有四级。

4

几何成阶梯

圆角 6/8/12/16/20、阴影 3 级、字号 7 档、间距 4 的倍数。不允许临时取值。

5

动效克制

180ms、ease-out、只做状态反馈；不做装饰性循环动画，尊重 reduced-motion。

判断标准：把截图缩小到 25% 看整体——如果某个色块第一个跳出来、且它不是主按钮，那就是过饱和。 本稿的目标是「一眼先看到内容和层级，颜色只在需要时出现」。

为什么卡片不用真模糊：一屏 5–8 张卡各带一层 backdrop-filter，滚动时 WebView2 每帧重算模糊， 既掉帧又让 12px 中文发虚（模糊层上叠文字是不稳定组合）。玻璃感来自「侧栏 + 浮层 + 柔光底」， 不来自每张卡片。

08技术路线

毛玻璃有两种做法：应用内 CSS 玻璃（可控、跨系统一致）与系统窗口效果（Mica/Acrylic，真透到桌面）。调研后只剩前者可行，原因见下。

关键结论：Mica 底 + CSS 磨砂玻璃这条路走不通

微软 WebView2 团队确认：WebView2 背景 alpha=0（透明窗口）时 backdrop-filter 没有"背后的像素"可模糊，等于失效，属 Chromium 设计而非 bug。 所以「窗口透出桌面壁纸 + 卡片在其上磨砂」无法实现，只能二选一：要么系统特效（锐利透出、Win11 only），要么应用内 CSS 玻璃。本稿选后者。

路线做法代价 / 风险结论
A · 应用内 CSS 玻璃 窗口底画「雾面底」（渐变 + 柔光斑 + 噪点），侧栏/浮层用 backdrop-filter 磨出层次。不动 tauri.conf.json、不动 Rust。 玻璃不会透到桌面；Win10 / Win11 表现一致；无需系统版本分支；回滚 = 一次 CSS revert。 本轮采用
B · 系统 Mica / Acrylic windowEffects + transparent: true（官方要求窗口必须透明），让窗口本体透出桌面壁纸。 Mica 仅 Win11（build ≥ 22000），Win10 直接无效；而透明窗口又会让 CSS 模糊失效；透明窗口历史问题一串：首帧白闪、文字渲染发虚、resize 掉帧、失焦失效。 本轮不做
C · 无边框自绘标题栏 decorations: false + 拖拽区 + 自绘最小化/最大化/关闭。 titleBarStyle 文档写明只对 macOS 有效；Windows 上丢 Snap Layouts（tauri#4531 仍 open）、拖边 resize 掉帧（#15569）、Win10 圆角/白边不一致；每次 Tauri 升级都要回归。 不建议

玻璃实现的 5 条硬约束

约束原因落地做法
祖先链上不能有 opacity / filter / mask它们会成为 backdrop root，子层的 backdrop-filter 只模糊"父与子之间"的内容，于是静默失效（最容易被 React 的入场淡入动画踩到）玻璃容器不做 fade-in；需要过渡时用 transform / 背景色，不用 opacity
同屏真模糊 ≤ 3 层每层每帧都要回读并重算下采样，滚动时成本随层数线性上升只给「侧栏 / 下拉 / 对话框」；内容卡一律磨砂纸（不做滤镜）
blur ≤ 20px、saturate ≤ 180%成本随半径与面积近似线性；超过 20px 观感也不再提升侧栏 24px 已是上限，浮层 20–30px 但面积小
玻璃层本身是新层叠上下文其内部的 fixed 子元素（下拉、Toast）会被困在层内，被相邻玻璃层盖住下拉/对话框/Toast 一律挂在 body 顶层（portal），不塞进玻璃卡
圆角与滤镜写在同一个元素父子各挂 radius 时模糊结果的裁切会出现亮边/漏光需要外壳裁切时：父层 overflow:hidden 不带滤镜，子层带滤镜
