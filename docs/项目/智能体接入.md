# 智能体接入（MCP）

Remote Mic 提供一个 **MCP（Model Context Protocol）stdio 接口**，让外部智能体
（Claude Code、Codex、DSH 等）读取和修改按键映射、触发时间等配置。

- **默认关闭**：必须在「通用设置 → 智能体接入」里手动打开开关。
- **仅本机**：接口只绑定 `127.0.0.1` 随机端口，token 只写入当前用户的
  `%LOCALAPPDATA%\RemoteMic\RC003\agent-api.json`。
- **只提供配置能力**：不暴露驱动安装、按键注入、更新、日志清空、语音桥控制等危险操作。

## 1. 开启

1. 打开 Remote Mic → **通用设置**；
2. 找到「**允许智能体配置（MCP）**」，打开开关；
3. 复制卡片里的 MCP 配置（或点「复制配置」）。

关闭开关会立即停止接口并删除 token 文件；正在运行的 MCP sidecar 下一次调用会得到
「智能体接口未启用」的可操作错误。

## 2. 配置智能体

把下面的 `mcpServers` 片段加入智能体的 MCP 配置（路径以实际安装目录为准）：

```json
{
  "mcpServers": {
    "remote-mic": {
      "command": "C:\\Program Files\\Remote Mic\\remote-mic-mcp.exe",
      "args": []
    }
  }
}
```

WSL 中的智能体建议用 Windows 互操作启动 `.exe`（需真机验证 stdio）：

```json
{
  "mcpServers": {
    "remote-mic": {
      "command": "/mnt/c/Program Files/Remote Mic/remote-mic-mcp.exe",
      "args": []
    }
  }
}
```

sidecar 每次调用前都会重新读取 `agent-api.json`，所以应用重启 / token 轮换后不需要改配置；
如果客户端缓存了旧进程，重启客户端即可。

## 3. 工具列表

| 工具 | 作用 | 读/写 |
| --- | --- | --- |
| `remote_mic_get_status` | 版本、连接/语音桥/旁路状态、revision | 读 |
| `remote_mic_get_mapping_catalog` | 按键/触发/动作目录与默认绑定 | 读 |
| `remote_mic_list_mappings` | 当前全局映射 + revision | 读 |
| `remote_mic_set_mapping` | 新增/修改一条绑定（保存即启用） | 写 |
| `remote_mic_clear_mapping` | 删除一条绑定 | 写（可逆） |
| `remote_mic_set_mapping_enabled` | 禁用/启用一条绑定 | 写 |
| `remote_mic_get_trigger_timing` | 长按阈值、双击窗口 | 读 |
| `remote_mic_set_trigger_timing` | 修改长按阈值、双击窗口 | 写 |
| `remote_mic_list_profiles` | 应用档案（只读） | 读 |
| `remote_mic_list_shortcuts` | 自定义快捷键 | 读 |
| `remote_mic_get_voice_target` | 语音识别目标 | 读 |
| `remote_mic_get_eat_mode` | 吃掉模式 | 读 |

说明：

- 动作参数优先用 `remote_mic_get_mapping_catalog` 返回的 `action_key`，自定义组合键用
  `combo:lctrl+k`；`disabled` 动作不再允许。
- 写入支持可选 `if_revision`：与当前 revision 不一致时返回 `conflict`，避免覆盖用户刚做的修改。
- 应用档案写入、快捷键写入、语音目标修改不在当前 MVP 暴露，后续版本再开。
- 工具失败时返回 `isError: true` 的结构化错误（`validation_error` / `conflict` /
  `app_not_running` / `unauthorized` 等），不是 JSON-RPC 协议错误。

## 4. 安全模型

- 开关默认关闭；关闭即停止监听并删除 token；
- 只绑 `127.0.0.1`，随机端口；32 字节 token；校验 `Host`，拒绝带 `Origin` 的浏览器请求；
- 限流 20 次/秒、请求体上限 64 KiB；
- 只读工具 `readOnlyHint: true`；删除类工具 `destructiveHint: true`；
- 应用不暴露危险操作；智能体侧仍应自行确认删除类操作；
- 残余风险：同一 Windows 用户下的其他进程理论上可以读取当前用户的 `agent-api.json`
  并调用接口；这是本机同用户信任模型的边界。

## 5. 故障排查

| 现象 | 处理 |
| --- | --- |
| `app_not_running` | 先启动 Remote Mic，并在通用设置打开「允许智能体配置（MCP）」 |
| `agent_api_disabled` | 开关被关闭；重新打开 |
| `unauthorized` | 应用重启轮换了 token；重启 MCP 客户端或重新复制配置 |
| `api_version_mismatch` | 应用与 sidecar 版本不一致；升级 / 重装 |
| 智能体看不到工具 | 确认 MCP 配置指向 `remote-mic-mcp.exe`，且客户端已重启 |
| WSL 启动失败 | 让 MCP 以 Windows 进程运行（WSL interop 启动 `.exe`） |

日志：应用日志在 `%LOCALAPPDATA%\RemoteMic\RC003\remote-mic.log`，搜索 `[agent-api]`；
sidecar 日志只写 stderr（stdout 必须保持纯 MCP 消息）。
