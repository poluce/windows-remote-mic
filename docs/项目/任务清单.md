  - [ ] **ATVV MIC_OPEN / MIC_CLOSE 主机侧握手（需真机验证后再启用）**
    - 现状：`mic_open_command` / `mic_close_command` 已在 `crates/core-atvv/src/protocol.rs` 定义，
      但**全仓库从未调用**；当前只发 `GET_CAPABILITIES_V10`，靠遥控器按键自行发起推流
      （实测 10-17 起可正常收流，说明 RC003 不强制要求主机 MIC_OPEN）。
    - 待验证（`docs/协议/ATVV-协议.md` 标注 ❓）：RC003 上两条命令的真实载荷与时序
      —— v1.0 推测 `0C 00` / `0D <session_id>`，旧版推测 `0C 00 00` / `0D`。
    - 关联事故：2026-10-15 遥控器语音服务挂起（连续约 26 小时 0 控制包、断链后仍无数据，
      断电复位才恢复）。**推断**与会话结束时未发 MIC_CLOSE、遥控器状态机未归位有关（未验证）。
    - 接入原则（禁止盲发默认开启）：
      1. 用一台官方 Android TV 盒子配同一遥控器，抓 HCI snoop（`btsnoop_hci.log`）确认真实报文；
      2. 或加一个默认关闭的 `config.json` 开关，仅在「会话结束/断开」时发 `MIC_CLOSE` + 详细日志，
         连续观察数日是否还会出现「链路已连接但零数据」；
      3. 长按 >20s 场景再试探 `MIC_EXTEND` 续期（硬件 Audio Transfer Timeout 约 15–60s）。
    - [ ] 真机抓包确认 MIC_OPEN/MIC_CLOSE 载荷与时序
    - [ ] 实现默认关闭的开关 + 日志
    - [ ] 真机对照验证（连续多日不再出现「链路通但零数据」）
    - [ ] 验证通过后默认开启，并更新 `docs/协议/ATVV-协议.md`（含 MIC_EXTEND）
